voice

Speech to text on this machine, for think-aloud answers, and a natural voice that reads the guide aloud.

This module turns a spoken answer into text. With the local engines, the audio does not go off the machine. The web app records while you talk. It cuts the audio into segments at your pauses and sends each segment here. This module transcribes the segments one at a time, in order. The text goes into the think-aloud box while you continue to talk.

The module also speaks. speak turns one line of the screen guide into WAV audio, with the start time of each word, so the board can light each word as it is said.

These are the imports of the module.

Engines

There are two engines. mlx runs on this machine. openai sends the audio to OpenAI.

  • mlx runs any speech to text model that mlx-audio can load. The default is Qwen3-ASR 0.6B (8 bit, 1.0 GB). Whisper large-v3-turbo is the second model on the Settings page, and the search finds the others. Install mlx-audio with pip install abhyasa[whisper].
  • openai uses the OpenAI transcription API. It is off until you set a key. It sends the audio off the machine.

Each engine gets a hint: the name of the concept and its terms. Qwen3-ASR reads it as hot words, Whisper as its initial prompt, and OpenAI as its prompt.

The table gives the numbers on this machine (an M-series Mac), with each model warm. “Clip A” is the English test clip of the model layer (rishi/nbs/speech.wav). “Clip B” is a clip in a cloned voice with Nyāya terms in IAST and technical terms. “Terms” is the fraction of the 9 key terms in clip B that the engine wrote correctly. “5 s” is the time for one 5-second segment.

mlx-community/whisper-large-v3-turbo-asr-fp16 4.8 s 0.68 s 6% 4% / 0% 8 / 9 10% 2.3 GB
mlx-community/Qwen3-ASR-1.7B-8bit 3.6 s 0.25 s 6% 6% / 0% 7 / 9 14% 3.6 GB
mlx-community/parakeet-tdt-0.6b-v3 4.9 s 0.15 s 6% 4% / 4% 7 / 7 Latin script 3.2 GB
mlx-community/Voxtral-Mini-4B-Realtime-2602-4bit 3.7 s 2.21 s 6% 6% / 6% 7 / 7 22% 5.5 GB

  • “load” is a cold start of a cached model in a new process, with the Python imports. The first download takes longer.
  • “memory” is the MLX peak.
  • “Sanskrit CER” is the character error rate on a 9-second Nyāya sūtra (from vachaka), after the vachaka normalization.
  • Moonshine gave no text for the 24-second clip A. It is good only for short segments.
  • For Sanskrit speech, use Qwen3-ASR or Whisper with the hint, or vachaka.

Qwen3-ASR 0.6B is the default. With the hint, it has no errors on clip B and it writes all 9 terms. One 5-second segment takes 0.14 s. Before 0.0.16, the default was Gemma 4 E4B on LiteRT. It had the same score, but it was 5 times slower, and its model was 3.7 GB.

DFLT_STT is the default model of the mlx engine. The other constants are the named models. ALIASES keeps the old engine names: whisper and parakeet are the mlx engine with a fixed model. gemma was the default engine before 0.0.16, so it becomes the mlx engine with the default model. POCKET is the Hugging Face repo of the local voice (see “A natural voice” below), and POCKET_FILES are the files of its English model and of its default voice. The repo has many languages, so abhyasa gets only these files.

Settings

The settings are in settings.json in cfg_dir(). The settings module keeps the table of values and the file; this module uses its stt section. The web app changes the settings, and the next segment uses the change. You do not have to restart.

Without a file, you get the defaults. A change to one key keeps the other keys.

test_eq({k: settings()['stt'][k] for k in ('engine', 'model', 'segment')}, dict(engine='mlx', model='', segment=True))
update_settings('stt', segment=False)
test_eq(val('stt.segment'), False)
update_settings('stt', segment=True)

current gives the engine and model in use. $ABHYASA_STT has priority over the settings. It can be an engine (mlx), an old name (whisper, gemma), or an engine and a model (mlx:mlx-community/whisper-large-v3-turbo-asr-fp16). An old settings file with gemma and a LiteRT model gets the default model. Nothing writes the file again.

One model in memory

resident keeps one model loaded in each slot: stt for speech to text, tts for the speaking voice. When the app asks for a different model in a slot, it frees the old model of that slot first. Two large models for the same job in memory at the same time can make the Mac slow.

Each engine is a function that takes a WAV path, a hint and a model, and returns text.

The mlx engine gives the hint to a model that accepts one: Whisper as initial_prompt, Qwen3-ASR as hotwords.

A Whisper-like model gets initial_prompt. A Qwen3-like model gets a list of hot words. A model without either gets nothing.

OpenAI

The openai engine posts the WAV to the OpenAI transcription API, with the hint as its prompt. http_post is httpx.post unless a test puts a fake in its place.

The key comes from the first of these places that has OPENAI_API_KEY: the environment, the abhyasa keys.env, then the ramabana keys.env. ramabana says where its file is ($RAMABANA_CONFIG, else ~/.config/ramabana/keys.env). abhyasa reads both files with ramabana’s load_keys. It refuses a file that other users can read, and it runs !command values. abhyasa only reads the ramabana file. set_openai_key writes the abhyasa file with save_key (atomic, mode 0600). ramabana is an optional extra. Without it, abhyasa reads and writes plain NAME=value lines. masked shows only the last 4 characters.

A natural voice

The board of the screen guide says one line for each step. The browser can say it with its own voice (speechSynthesis), but that voice sounds like a machine. speak gives a natural voice. There are two engines:

  • pocket runs Kyutai’s Pocket TTS on this Mac, with the pocket-tts-mlx package. The download is 225 MB. It has 21 English voices, and it makes a line of 4 seconds in less than 1 second. Install it with pip install abhyasa[voice].
  • openai sends the line to the OpenAI speech API. It is off until you set a key. Each line passes ramabana’s guard first.

browser is the third choice of the setting voice.out. Then the page speaks, and this module makes no audio. The default is pocket. Until its model is on this Mac, the browser speaks: Speaker refuses the line with the word “browser”, and the page uses its own voice.

Licences: the pocket-tts-mlx code is MIT. The Pocket TTS weights (kyutai/pocket-tts-without-voice-cloning, by Kyutai) are CC-BY-4.0.

These are the defaults. POCKET_VOICES are the 21 English voices of Pocket TTS. caro_davy is first: the owner chose it by ear. The OpenAI voices are the voices of its speech API.

out_resolve fills in the default model and voice of an engine. Before 0.0.16 the local voices were kokoro and hf: they become pocket, and a voice that Pocket does not have becomes caro_davy. Thus an old settings file works, and nothing writes it again. out_current gives the voice of the settings, with its speed. out_where says where the voice runs.

The time of each word

The board lights each word when the voice says it. Pocket TTS and OpenAI give no word times. Thus by_letters shares the length of the audio among the words by their letters.

Pocket TTS

_pocket loads the model one time into the tts slot of resident, and keeps the state of each voice that it used. _pocket_say makes the audio of one line. normalize=True makes the voices equally loud: some, such as stuart_bell and peter_yearsley, are quiet. Pocket TTS has no speed, so the speed setting is only for OpenAI. When pocket-tts-mlx is not installed, the error says how to install it.

OpenAI

The openai engine posts the line to the OpenAI speech API and asks for WAV. instructions can set the tone (“calm, like a teacher”); only the gpt-4o models read it. The owner’s rule is that each text that goes to a hosted model passes ramabana’s guard (abhyasa.guide.guard, with ramabana.guard.outgoing). It masks a secret and refuses personal data when the privacy setting says so.

One worker for the voice

Speaker has one worker thread for all the calls of the speaking voice, separate from the speech to text worker. Thus a line of the board does not wait for a segment of dictation. It keeps the lines that it said in this run (at most most), by engine, model, voice, speed and text. The board asks for the same line again when the learner goes back a step, and that line then comes at once. Two requests for the same line share one call. warm loads the model in use with one short line, so the first line of a board does not wait for the load. The browser voice and OpenAI have nothing to load.

A model that is not on this Mac yet is not downloaded for a line: the Settings page shows its download. Until then, say refuses the line with the word “browser”, as for the browser voice, so the page and the Mac app speak with their own voice.

source

A fake voice counts its calls. The same line comes from the cache, and a new speed is a new line.

Segments in order

The browser sends one segment each time you stop to think. Speech has one worker thread for all the model calls. Thus only one model is in memory, and the segments run one at a time, in the order they came. A Dictation collects the segments of one answer. next gives the text in the order of the segment numbers, also when a slow request arrives late. When the browser sends a segment again (after an error), the code does not use it two times.

source

Dictation

def Dictation(
    speech, hint:str=''
):

The segments of one spoken answer: each is transcribed on the speech worker, and the text comes out in order.

Speech owns the worker. warm loads the model in use with half a second of silence, so the first segment does not wait for it. use changes the engine and model, saves the change, and warms the new model.
