tutor

The loop: pick, ask, let the learner struggle, grade, update, teach the smallest step.

This module runs the learning loop. pick chooses the concept and the depth, and a model writes the question. The learner answers and can ask for hints. The model grades the answer, and the learner model updates the concept. After a miss, the tutor teaches the smallest step. Each surface (the web app, the ramabana terminal agent, a notebook) uses Tutor and Session.

Import the tools that this module uses, and the other abhyasa modules that the tutor calls.

Tries and hints

A wrong answer does not end the question. The tutor names the first error, gives no fix, and the learner tries again. After the tries of the setting checks.tries (3 by default), or when the learner stops, the tutor teaches the smallest step. Then the state of the concept records the miss. A pass after a wrong try counts as fragile. The best try counts: each try keeps its grade. When a try had the grade of checks.near (7 by default) or more, the close is a fragile pass, not a miss, because the learner had the idea.

Each open question keeps a thread, q.turns: the question, then each message of the learner and each reply of the tutor, in order. A message of the learner is only what they say this time, often a follow-up to the last nudge. They do not send the full answer again. The grade, the hints and the lesson read the whole thread.

HINTS is the hint ladder, from the least to the most revealing. The model gets one rung for each hint request.

DEPTH_ASK tells the model what a question at each depth must make the learner do. It is the prompt depths, one line for each depth, so you can change it on the Settings page. depth_ask reads it when a question is written.

Prompts

Each prompt function makes the text for one model call. The prompt text is an instruction to the model.

QUESTION_RULES is the fixed instruction for each new question. A question asks one thing, in under 60 words and in plain words. Pairs of a bad and a good question show each rule. asks_twice is a quick check on a written question: it finds a second ask after a comma, or a second question mark.

Prompts that you can change

The instruction text of each prompt is in the registry of prompts, so you can change it in Settings. The constants stay as the defaults. A prompt function reads the text when it runs, so a change works on the next question. hints gives the hint ladder in use. A saved ladder must have 6 lines, and a lesson instruction must keep the ‘Check:’ line.

Open questions on the shelf

The tutor keeps each open question in memory, and also on the shelf as a document of kind open-q. The document has the full question: the text, the concept, the kind, the options, the answer key, the tries, the hints, the confidence, the session and the walk step. Only the server reads it. A restart of the app thus loses no open question.

put_open_q writes the document under the lock of the question. A closed question stays on the shelf with its status and its end (closed, dropped or abandoned), so that an old copy, such as the open question in a session document, cannot open it again. open_q reads it.

Stop and teach

give_up closes the question as a miss, unless an earlier try was graded checks.near or more. _close updates the concept, teaches after a miss and records the attempt. Before the lesson, a function in LESSON_HOOKS can pick another way for the lesson. The result names that way in lesson_way. Then each function in CLOSE_HOOKS can add to the result. The demo module uses this hook to attach a demo after a miss. The confidence of the first try counts, because the first try shows what the learner believed.

A session

Session keeps one sitting together. Its id goes on each attempt, and it stops after limit questions (by default, the session length in the profile of the learner). It asks about one concept for at most run questions in a row. This lets the range between floor and ceiling close, and it keeps the learner interested.

A session is saved on the shelf after each move: when a question opens, after each answer and hint, and at the end. It keeps the log of each closed question (with the floor before and after, and the thread) and the open question with its thread. Thus Session.load continues it after a restart, with the same question, graded the same way.

A session in a walk asks about the current step of the walk. When the step is learned, the next question is on the next step.

source

A check right after a lesson shows that you understood it. It does not show that you will remember it, because the lesson is still in your mind. A pass right after the miss does not count.

A fake model plays the tutor. Its grader passes an answer only when the answer has the words “rank position”. Two concepts are on the shelf, and Reciprocal rank fusion needs Ranking.

from abhyasa.store import temp_learning
from abhyasa.llm import Fake
lr = temp_learning()
lr.put('Ranking', 'Order items by a score.', 'ml', order=0)
lr.put('Reciprocal rank fusion', 'Merge ranked lists by summing 1/(k + rank).', 'ml', prereqs=['ranking'], order=1)
def grader(p, sp):
    ok = 'rank position' in p.split("Learner's answer:")[1]
    return dict(correct=ok, grade=8 if ok else 3, first_error='You add raw scores.',
                               misconception='scores are comparable across systems', feedback='Look at what each list really shares.')
fake = Fake({'You grade one answer': grader, 'Give hint level': 'Look at what the two lists have in common.',
             'Teach the smallest step': 'Only positions are shared. Check: what happens with k = 0?',
             'Write ONE question': dict(question='Why does RRF use ranks, not scores?', answer='Scores are not comparable.', rubric=['ranks are comparable'])})
t = Tutor(lr, fake, context=False)

test_eq((val('checks.open_days'), SETTINGS['checks.open_days'].lo, SETTINGS['checks.open_days'].hi), (7, 1, 60))
xq = ot.ask_on(ol.concept('ranking'), 3); ot.answer(xq.id, 'sum the scores', confidence=40)
before, n = dict(ol.concept('ranking')), len(ol.attempts('ranking', limit=None))
ol.v.set_meta(ol.open_q(xq.id).doc_id, updated=time.time() - 8 * 86400)
assert xq.id not in Tutor(ol, fake, context=False).open
test_eq((ol.open_q(xq.id).status, ol.open_q(xq.id).end), ('closed', 'abandoned'))
test_eq((dict(ol.concept('ranking')), len(ol.attempts('ranking', limit=None))), (before, n))

With a longer setting, the same age is not too old.

yq = ot.ask_on(ol.concept('ranking'), 3)
ol.v.set_meta(ol.open_q(yq.id).doc_id, updated=time.time() - 8 * 86400)
set_val('checks.open_days', 10)
try: assert yq.id in Tutor(ol, fake, context=False).open
finally: reset('checks.open_days')

A session after a restart

A session question keeps its hints after a restart. end closes the question on the shelf.

sl2 = temp_learning(); sl2.put('Ranking', 'Order items by a score.', 'ml')
s1 = Session(Tutor(sl2, fake2, context=False), limit=3)
sq = s1.next(); s1.hint()
back2 = Session.load(Tutor(sl2, fake2, context=False), s1.id)
test_eq((back2.q.id, len(back2.tutor.open[sq.id].hints)), (sq.id, 1))
back2.end()
test_eq((sl2.open_q(sq.id).status, sl2.open_q(sq.id).end), ('closed', 'dropped'))
test_eq(Session.load(Tutor(sl2, fake2, context=False), s1.id).q, None)

An old vault has no open-q documents, and its session document has the full open question. That question still loads, and the shelf then keeps it.

sl3 = temp_learning(); sl3.put('Ranking', 'Order items by a score.', 'ml')
s3 = Session(Tutor(sl3, fake2, context=False), limit=3); q3 = s3.next()
sl3.v.set_meta(sl3.session(s3.id).doc_id, open=dict(s3.tutor.open[q3.id]))   # an old vault: the full question in the session document
sl3.v.forget(sl3.open_q(q3.id).doc_id)
back3 = Session.load(Tutor(sl3, fake2, context=False), s3.id)
test_eq((back3.q.id, sl3.open_q(q3.id).status), (q3.id, 'open'))

A session document with a closed question does not open it again.

sl3.put_open_q(back3.tutor.open[q3.id], 'closed', 'closed')
test_eq(Session.load(Tutor(sl3, fake2, context=False), s3.id).q, None)

One caller at a time

Two tabs can send an answer to the same question at the same time. The lock of the question lets one caller work on it at a time. To make the overlap sure, this grader waits a moment before it grades.

These tests use threads and the garbage collector.

import gc, threading as th
def slow(p, sp):
    time.sleep(.2)
    ok = 'rank position' in p.split("Learner's answer:")[1]
    return dict(correct=ok, grade=8 if ok else 3, first_error='You add raw scores.', misconception='', feedback='Look again.')
slow_fake = Fake({'You grade one answer': slow}, dflt=dict(question='Why ranks?', answer='Positions.', rubric=['positions']))
def both(f, *args):
    "Run `f(*a)` for each `a` in `args` in two threads at once. Return the results; a KeyError is the result `'gone'`."
    out = [None] * len(args)
    def go(k):
        try: out[k] = f(*args[k])
        except KeyError: out[k] = 'gone'
    ts = [th.Thread(target=go, args=(k,)) for k in range(len(args))]
    for x in ts: x.start()
    for x in ts: x.join()
    return out

After a restart, two wrong tries at once both count. The tutor loads one copy of the question, so no try is lost.

cl_ = temp_learning(); cl_.put('Ranking', 'Order items by a score.', 'ml')
cq = Tutor(cl_, slow_fake, context=False).ask_on(cl_.concept('ranking'), 3)
ct = Tutor(cl_, slow_fake, context=False)   # a restart
set_val('checks.tries', 5)
try: rs = both(lambda a: ct.answer(cq.id, a), ('a sum',), ('a mean',))
finally: reset('checks.tries')
test_eq(sorted(r.tries_left for r in rs), [3, 4])
test_eq(sorted(t['answer'] for t in cl_.open_q(cq.id).q['tries']), ['a mean', 'a sum'])

Two right answers at once close the question one time. The second caller finds no open question and gets a KeyError, which a page shows as a closed check.

rs = both(lambda a: ct.answer(cq.id, a), ('the rank position',), ('the rank position',))
test_eq(sorted(map(str, [r if r == 'gone' else r.done for r in rs])), ['True', 'gone'])
test_eq(len([a for a in cl_.attempts('ranking', limit=None) if a.get('final')]), 1)

The session document keeps only the learner view of its open question, with no answer key. The open-q document has the full question.

s4 = Session(Tutor(cl_, fake2, context=False), limit=3); q4 = s4.next()
o = cl_.session(s4.id).open
assert o['id'] == q4.id and 'answer' not in o and 'rubric' not in o and 'answer' in cl_.open_q(q4.id).q

A learner view in a session document never opens as a question. With no open-q document, the session loads with no open question.

cl_.v.forget(cl_.open_q(q4.id).doc_id)
test_eq(Session.load(Tutor(cl_, fake2, context=False), s4.id).q, None)

The locks do not grow without end: a lock that no caller holds goes away.
