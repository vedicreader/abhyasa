store

The learning shelf: concepts, attempts and sessions as vault documents.

This module keeps all learning data in your vault, on one shelf named learning. Each concept, attempt and session is one vault document. Thus each tool that reads the vault can search it. The other modules read and write the shelf only through the Learning class in this module.

Import the tools that this module uses, and the Vault class of the vault.

The shelf

Search reads the text of a document. The meta JSON keeps the state. Vault.set_meta changes the state and does not embed the text again. The table gives the source URI of each kind of document.

kind source
concept learning://concept/<slug>
attempt learning://attempt/<id>
session learning://session/<id>

These constants name the shelf, give the start state of a concept, and list the fields that merge.

slugify makes the key of a concept from its name. It changes a name in an Indic script, such as Devanagari, to IAST first. It changes +, # and & to words, so C, C++ and C# get different slugs. A name with no letters that it can read gets a short hash of the name. Thus the same name always gives the same slug. _src makes the source URI of a document.

Shelves of documents

A vault file holds more stores than the shelves of documents. For example, the vault keeps the names that it finds in a store named entities. That store has no doc_id column and no docs table. doc_shelves gives only the shelves that hold documents. doc_shelf opens one of them, or gives None. It never makes a new shelf, so a name in a link or in an old walk does not add a store to your vault.

Move old slugs

abhyasa 0.0.5 and older made slugs in a different way. A name in Devanagari got a random slug, and C, C++ and C# got the same slug, c. reslug finds each concept that has an old slug. It moves the concept to the slug that slugify gives now. It also changes the slug in each place that points to it: the links of other concepts, attempts, sessions, walks and demos. A slug that a source sets, such as sa-term-karaka, does not change.

reslug finds the moves first. With dry_run it stops there and writes nothing.

Groups

A concept can sit in a group under its subject. For example, Magha sits at jyotisha › nakshatras › Magha. The path is a list of at most two short names in the group field. group_by tells who set it: hand for the learner, model for the tutor. The tutor never moves a concept that the learner moved by hand. An old vault has no groups, so each concept shows under “Not sorted yet”.

clean_group makes a path safe to keep and to show. Each name has only letters, digits, spaces and hyphens, and at most GROUP_LEN characters.

source

set_group moves one concept. A move by hand marks it. A move by the model does not change a concept with the mark. An empty path by hand also keeps the mark: the learner chose no group, so the tutor does not sort the concept again. groups lists the paths in use under one subject, with their parents, so a new concept can go in a group that is there.

Sort by hand

You can sort the concepts yourself. rename gives a concept a new name and marks it named_by='hand', so a new extract never renames it. The old name stays as an alias, so the find box still finds it. rename_group gives a group a new name. Each concept in the group, or in a group below it, gets the new name and group_by='hand'. A name that is the name of a group beside it, in any case and without marks, joins the two groups. new_group adds an empty group. hand_groups lists the groups that you made or renamed. “Sort everything again” keeps them. snapshot and restore are the Undo of one change by hand: snapshot keeps the fields that a change by hand can touch, and restore writes them back.

Search and graph

search uses the hybrid search of the vault. Each hit has the kind, title and meta of its document. The method stats, the marker of a repair, a session with no answers and an open question stay out of it. Two attempts with the same text show as one hit. graph gives the nodes and links for the graph view.

Shelves of documents

A real vault also keeps a store of names, entities, with no doc_id column. doc_shelves leaves it out. It keeps the main shelf, the learning shelf and a shelf of notebooks.

dv = temp_learning()
dv.vault.shelf('notebooks').add('Notes on softmax.', title='nbs/softmax', source='/x/softmax.md', kind='md')
dv.vault.db.get_graph('store', ann=False)   # the store of names, as vishalakshi makes it
assert 'entities' in dv.vault.db.table_names()   # the store of names is in the vault, though vishalakshi 0.1.36 no longer lists it as a shelf
test_eq(sorted(dv.doc_shelves()), ['learning', 'notebooks', 'store'])

doc_shelves reads only the names of the stores. It does not count the documents of each store, so SQLite logs no error for a store of names with no docs table. A page can call it many times.

import logging
class _Seen(logging.Handler):
    def __init__(self): super().__init__(); self.got = []
    def emit(self, r): self.got.append(r.getMessage())
seen, root = _Seen(), logging.getLogger()
root.addHandler(seen)
try: test_eq(sorted(dv.doc_shelves()), ['learning', 'notebooks', 'store'])
finally: root.removeHandler(seen)
test_eq([m for m in seen.got if 'no such table' in m], [])

doc_shelf opens a shelf of documents. It gives None for the store of names and for a name that is not in the vault, and it does not make that shelf.

test_eq(dv.doc_shelf('notebooks').t.docs()[0]['title'], 'nbs/softmax')
test_is(dv.doc_shelf('store'), dv.vault)
test_is(dv.doc_shelf('entities'), None)
test_is(dv.doc_shelf('nope'), None)
assert 'nope' not in [s['store'] for s in dv.vault.shelves()]
