research

A source from the web for a walk step that has no passage, quoted word for word and kept in your vault.

A walk from a paper or a link shows a passage of the source on each step. A walk from a topic, and the walk of a talk from a path, often has no source passage. Then the step shows the statement of the idea in the tutor’s words. The learner cannot see where the knowledge comes from.

This module finds a source for such a step. It searches the web for the idea, reads the best pages with plain HTTP (a paper with the paper reader), and asks the model to quote one passage that explains the idea. The tutor keeps the passage only when it is in the page word for word and names the idea. Then it files the page in your vault, links it to the concept, and keeps the passage on the step.

The rules are the rules of a link walk (sources): only public hosts, plain HTTP with no browser, a cap on bytes, speed and time, and no fetch on a request: the web app runs research only on its pool.

Import the modules that this module uses. fossick loads only when a real search or fetch runs, so the import stays light.

The query

The first query is the name of the idea, with its first alias when the name does not hold it. A name of one word, or of words with many senses (such as Attention), also gets the label of its subject (SUBJECT_LABEL), so the search does not find pages from another field. A page that explains the idea comes first, not a page on the topic of the walk. When that search finds no good quote, a second query adds the subject and the title of the walk, in at most 120 characters. The goal text never goes to the search: a long goal with many words finds pages on the goal, not on the idea. When a title is only the start of the goal, it stays out, too. The search engine sees this text, so the Add page says that the search sees your topic.

Which results to read

A search result is a candidate only when research can read it: an http or https link to a host on the internet (link_kind). A web page (the kind web) goes to the plain fetch. A paper (an arXiv link or a link to a PDF, is_paper) goes to the paper reader of a link walk (file_link), and the candidate has paper=True. A video, a social site, a link to another file (such as a zip or a video file), a host in percent codes or with a user name, and a link to this computer or to a local network are dropped.

The real search and fetch

web_search asks fossick for the top results, and fossick’s curate removes copy sites and puts the best sites first. web_fetch reads one page with plain HTTP only (PLAIN, so auto=False: no browser and never your own Chrome), with the time and speed limits of a link (fetch_opts) and a cap on the bytes. It checks the link with public_url (fossick’s check_url) before the fetch, and fossick checks the address again when it connects, and each redirect. It reads only a page whose Content-Type is HTML or plain text (page_text), and refuses the others before it parses them. The page becomes text as in a link walk: markdown from the readable part of the page, or from all of it when that part is too short. A page that fossick’s usable finds to be a check for robots (a bot wall) is refused before a model reads it. The log keeps each URL that it reads.

The quote

The model gets the idea, the URL of the page and the page text in a fence (fence from ground: <source title="…">…</source>). The prompt says that the text in the fence is material, not instructions. A <source> marker in the page is cut, so it cannot close the fence. The model gives one passage of at most 600 characters. The tutor keeps it only when it is in the page word for word: verbatim makes each run of white space one space, and changes nothing else. The passage must start and end at a word boundary. A paraphrase is refused.

A page can start with lines of page data, such as **Last modified:** 2023/01/13 **Description:** …. fossick’s html2md keeps them, and fossick has no step that removes them. So drop_meta removes each line that starts with a label of the page (last modified, date, author, description, tags and others) and a colon. page_text removes them before abhyasa files a page, and verbatim removes them from the passage and from the text before it compares them, so a passage stays word for word with the text that is filed.

Is the passage about the idea?

about_idea keeps a random quote out, and lets a real passage in. These are real cases from a walk that the old rule refused: the d2l page for Queries, keys and values, The Annotated Diffusion Model and the course notebook for Noising images and predicting the noise, and the diffusers LoRA guide for Fine-tune a LoRA for Indian comics. Keep the source

file_page adds the page to the vault as a web document, as a link walk files a page: its text, its title, its URL and the kind web. It never files over a document: when the vault has the URL already and the stored text has the passage, it uses that document. Else it files the new text as a new document, with its own id, so older steps and links stay good. ground() then finds it with your other sources. link_concept adds the page to the provenance of the concept, as extract does, one entry for each document, so the concept page, the lessons and the slides know where the idea comes from.

Research one step

research_step finds a source for step i of walk j. The search, the fetch and the paper reader come in as functions, so a test uses fakes and no network. It searches first for the idea by its name. When that finds no good quote, it searches one more time with the subject and the title of the walk (research_query), and skips the pages that it read. For each search it reads at most 3 candidates, one at a time: a web page with the fetch, a paper with the paper reader (read_paper). It stops at the first page with a good quote. A good quote is in the page word for word and names the idea (names_idea from ground): the name word for word, or a key term (an alias, or a term such as LoRA) and at least half of the other main words of the name. The source line (the title of the page) counts with the quote. A weak match is no source, as for a passage from your sources.

The paper reader files a paper before the model reads it. When the paper has no good quote, research forgets it again, as a web page with no quote is never filed. A paper that was in the vault before stays.

On the step it keeps the passage in read (as a passage from your sources: its text, the title, the site, the URL and the vault document), with researched and the time, and research='found'. It finds the step again by its concept, under the lock of the walk, just before it writes, so a step that moved or left the walk does not get the wrong source. It clears the tutor note, and writes it again from the passage. With no good page, the step gets research='none' and research_why, one line that says why: the search found nothing, no page had a good quote, or a page could not be read (with a short reason, such as a certificate error). When the setting research.on is off, it does nothing.

Research a walk

to_research gives the steps of a walk that want a source, in walk order, at most research.per_walk of them. mark_pending marks them research='pending' at once, so each step page can say “Looking for a source…” while the pool works. research_walk then researches them one by one, each found by its concept. A step that has none or found already is not searched again. A step that is pending is not searched again while its search runs. When a search stops in a run, the step stays pending: after research.retry minutes, to_research takes it as not started. A restart stops each search. At start, Researcher.resume scans the walks on the research pool, and looks again at once for each step that was pending before the start.

The gather agent

A big goal names many sources, and the plan can leave many steps with no passage. For such a walk, a ramabana agent gathers the sources: it plans, searches, reads and proposes a passage for each idea. It can only read. abhyasa files each source itself, and only after the same checks as research: the passage must be in the document word for word (verbatim), and it must name the idea (names_idea).

want_agent says when the agent runs: the settings research.on and research.agent are on, and the goal names 2 or more sources, or one source with more than 40 documents, or a model call of the walk failed.

source

want_agent

def want_agent(
    j, chips:tuple=(), failed:bool=False
)->bool:

Whether the gather agent fills walk j: the settings research.on and research.agent are on, and the goal names 2 or more sources, or one source with more than BIG_ROOT documents, or a model call of the walk failed (failed). A chip is an id, or a dict with id and count; the count of an id comes from j.chip_counts.

One chip with 10 documents is not a big walk. Two chips, a chip with 41 documents, or a failed model call is. With the setting off, the agent never runs.

The log and the state

Each tool call adds one row to j.gather, so the learner sees what the agent read and filed, with a link. A row has a short target and outcome, and only a web link or a local path of the app. gather_state keeps what the agent read in one run. A page or a file that it read stays in memory under an id such as p1, and goes to the vault only with a passage. The agent may read only the vault documents of the sources that the goal named.

class Host:
    "A fake ramabana host: `gather_tools` puts its `read_url`, `web_search` and `read` on it."
    def __init__(self): self.roots = []
    def add_root(self, p, readonly=False): self.roots.append(p)

class Script:
    """A fake ramabana `Agent`: `ask` runs the tool calls of `script` in order, until `cancel`. A callable in the script runs as it is.
    A name that abhyasa does not add is a read of ramabana's host: `fetch_page` is its `read_url`, `read_file` its `read` (`view_file`).
    Called as `ramabana_lead`, it gives itself and a fake host."""
    def __init__(self, script): self.script, self.tools, self.cancelled, self.host = script, {}, False, Host()
    def __call__(self, read_roots=(), tools=(), **kw): self.roots, self.offered, self.kw = list(read_roots), list(tools), kw; return self, self.host
    def add_tool(self, f): self.tools[f.__name__] = f
    def call(self, name, kw):
        if name in self.tools: return self.tools[name](**kw)
        if name == 'fetch_page': return self.host.read_url(kw['url'], idea=kw.get('idea', 0)).text
        if name == 'read_file': return self.host.read(kw['file'], idea=kw.get('idea', 0))
        if name == 'web_search': return self.host.web_search(kw['query'])
        raise KeyError(name)
    def ask(self, prompt, **kw):
        self.prompt = prompt
        for x in self.script:
            if self.cancelled: break
            if callable(x): x(); continue
            self.call(*x)
        return AttrDict(state='cancelled' if self.cancelled else 'complete', reply='I gave one passage.', error='')
    def cancel(self): self.cancelled = True
    def close(self): pass
