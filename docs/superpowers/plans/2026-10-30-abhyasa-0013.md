# abhyasa 0.0.13 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make abhyasa easy for a new person: one word ("walk"), four tabs, one Start box, a visible source on every passage, calm editors for a talk and a walk path, hand sorting of concepts, and arXiv passages that keep their maths.

**Architecture:** The web app stays made of blocks that never import each other. New page parts go through new hooks in `core/hooks.py` (`learn_talks`, `learn_start`, `learning_top`). Pure logic goes into engine notebooks: `nbs/19_detect.ipynb` (what the Start box reads) and `nbs/20_edit.ipynb` (edit history, rewrite, walk edits, "Make it again"). The shared editor UI (`core/edit.py`, `core/edit.js`) serves both editors. A new stdlib-only module `abhyasa/stagekit.py` lets Leela import `room_spec` and `is_local` with no web code.

**Tech Stack:** Python 3.13, FastHTML and htmx, nbdev 3 on hatchling, vishalakshi vault, fossick (plain fetch), KaTeX, pytest, Playwright bundled Chromium.

**Spec:** `/Users/71293/code/personal/orgs/abhyasa-designs/0.0.13/notes.md` (agreed items, owner decisions, items 12-17), `design.md` (the study), `open-questions.md` (all 8 recommendations accepted), `mockups/*.html`. Owner additions (a) to (e) of 29 Oct are copied into the tasks below.

## Global Constraints

- Engine code is in `nbs/*.ipynb`; never edit a generated `abhyasa/*.py`. Run `uv run nbdev-prepare` (hyphen) after each notebook change. `abhyasa/stagekit.py`, `abhyasa/app.py`, `abhyasa/core/`, `abhyasa/blocks/` are hand-written.
- A block never imports another block. Blocks talk through hooks in `core/hooks.py`; each new hook is named in the `hooks.py` docstring.
- `connect` registers every route in one place at its end. A new block capability goes in its `CAPS`.
- One word for one thing: "walk" on every page, button, key sheet, doc and the Leela reuse notes. A plain journey is "a walk with no source" with the pill "path". A side walk stays "side walk". Code names (`journey`, `lr.journey`, `abhyasa.journey`, `put_journey`, `mode='walk'`) do not change: Leela imports them.
- Learn pills: `path`, `paper`, `topic`, `repo`, `site`, and `text` for a pasted text (a text is not a paper; decision 6 uses the same reason).
- Source labels, as pill text: `your source`, `from the web`, `tutor`, `you`. Tutor text has a dashed rule, the words "In the tutor's words", and no link. A tutor note under a passage has the label "The tutor's note". A speaker note has the label "Your note".
- Start box label: "Paste a link, a paper, a topic, a file name or some text". Main button "Start", key `⌥S`, filled only when the box has text.
- One-time web line: "The tutor will search the web for sources. Your topic goes to the search. Turn this off in Settings."
- The Start box reads the text only. It makes no network call before Start. The only lookup is a local match of vault document titles.
- Keys: `⌥T` Today, `⌥Q` Learn, `⌥R` Library, `⌥G` You, `⌥1` `⌥2` `⌥3` pick a sub-tab, `⌥C` Continue, `⌥F`/`?` keys page. No Settings key. The talk presenter window ignores all tab keys.
- Editors: no Save button; a field saves on blur or after 600 ms with no typing; the Undo bar says what changed in one sentence and stays 8 seconds; `⌘Z` undoes; history keeps 50 changes per talk or walk; no confirm dialog on Remove.
- A rewrite changes tutor text only. A passage changes only when the person picks another real passage, word for word from a source.
- The hands-on share only warns: "Hands-on: 6 of 12 ideas (50%). Your setting is about 33%." with a link "Change the setting" to `/settings`. A tool walk never offers "Write code".
- A concept or group touched by hand gets `named_by='hand'` / `group_by='hand'`; the tutor never changes it.
- Every old URL keeps working: `/journeys`, `/j/{jid}` and its POST routes, `/add` (GET and POST), `/add/vedicreader`, `/walk/new`, `/you/strengths`, `/talk/new`, `/talk/journey`, `/journeys/new`, `/journeys/attach`. A GET moves with a 303 redirect; a POST keeps its handler at the old path.
- No in-app link has `/learn?` in its href: `tools/walk_look.py` (check near line 668) uses that pattern to find Leela links. Abhyasa's Learn page is `/learn` with no query; the Start box focus is `/learn#start`.
- UI text, docs, CHANGELOG and commits are ASD-STE100, US grade 9. Commits are one plain line with no AI credit and no Co-Authored-By line.
- Tests use `temp_learning()` (through the `lr`/`mk` fixtures in `tests/conftest.py`); never the real vault. Browser checks use `tools/walk_look.py` and `tools/talk_look.py` (bundled Chromium, headless, one browser at a time). No test raises a window or takes focus.
- Every task ends with `uv run nbdev-prepare` (when a notebook changed) and `uv run pytest -q` both green. Tasks run in order, one at a time: almost all share `core/ui.py`, `abhyasa/_modidx.py` or a notebook, so none run in parallel.

## Review Focus

1. **A started walk is edited.** Step pages are `/w/{jid}/{i}` by index; a side walk stores `parent.step` (an index); an open check stores `qid` on its step; research writes by slug (`research.put_step`). A move, a remove, a split or a merge must keep the progress of each step that stays, keep side walks pointing at the right step, and keep a research write that lands during the edit. Test: Task 9 `test_reorder_keeps_progress_side_walks_and_research`.
2. **Undo after a background write.** An undo restores a snapshot of the slides or steps. A step whose source research found after the snapshot keeps that source, and run fields (`done`, `qid`, `note`, `read_at`) always come from the current walk. Test: Task 7 `test_undo_keeps_run_fields_and_research`.
3. **Odd text in the Start box.** Empty or only spaces, `arxiv:1706.03762v5`, an arXiv link with spaces around it, `http://127.1/`, a name with marks such as "nakṣatra", one line of 300 characters, a URL with no scheme such as `github.com/a/b`. Each gives a reading, never a network call, never an exception. Test: Task 5 `DETECT_CASES` and `test_detect_never_touches_the_network`.
4. **Old bookmarks and old open pages.** A bookmark to `/journeys`, `/j/{jid}`, `/add` or `/you/strengths`, and a form posted from a page opened before the upgrade (`POST /j/{jid}/step`, `POST /add`). Each works. Tests: Task 2 `test_old_journey_routes_still_work`, Task 4 `test_old_list_routes_redirect_to_learn`, Task 13 `test_strengths_route_still_answers`.
5. **Group names that differ only in case or marks.** Renaming a group to the name of another group in the same subject ("Padas" into "padas") merges them: one group, all concepts in it, all marked by hand, no duplicate in the saved list. Test: Task 11 `test_rename_into_existing_group_merges`.

  - `read_arxiv_html(aid:str, fetch=None) -> AttrDict(title, text, figures)|None` — one plain fetch (`PLAIN`, `fetch_opts()`, at most `research.PAGE_BYTES`); None on any error, a status other than 200, no `ltx_document`, or text shorter than `SHORT`. `figures` are the image links under `https://arxiv.org/html/{aid}/`, at most `ARXIV_FIGS`.
