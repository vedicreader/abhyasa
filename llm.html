llm

One call shape for each model: ask(prompt, sp) -> str.

This module connects the tutor to a model. The tutor needs only one function, ask(prompt, sp), which returns text. The module also parses JSON replies and gives Fake, a model for tests that runs offline.

Import the tools that this module uses.

The model

Each surface gives its own ask.

surface ask
web app route_ask: each call goes through the routing of ramabana, on a backend that stays open
notebook rishi_ask: a new Chat of the model layer for each call
the ramabana terminal agent agent.oneshot, so the routing of the agent applies
tests Fake

The default model is --model, else $ABHYASA_MODEL, else DFLT_MODEL (claude/sonnet).

source

parse_json

def parse_json(
    s:str
):

The first JSON object or array in s, also inside a ``fence. RaiseValueError` when there is none.

parse_json reads JSON in a fence, JSON inside other text, and arrays. A fence inside a JSON string does not break it. It fails when there is no JSON.

test_eq(parse_json('```json\n{"a": 1}\n```'), {'a': 1})
test_eq(parse_json('Here it is: {"a": [1, 2]} thanks'), {'a': [1, 2]})
test_eq(parse_json('[{"x": 1}]'), [{'x': 1}])
test_fail(lambda: parse_json('nothing'), contains='no JSON')
test_eq(parse_json('{"answer": "Use ```python\\nx = 1\\n``` here."}'), {'answer': 'Use ```python\nx = 1\n``` here.'})
test_eq(parse_json('Sure. {"a": 1} and then {"b": 2}'), {'a': 1})

A model for tests

Fake replies from a dict of rules. The first rule with a key in the prompt gives the reply. It sends a dict or a list reply as JSON. It keeps each call in calls.

source

Fake

def Fake(
    rules:dict=None, dflt:str='{}'
):

A stand-in model for tests: Fake({'grade': {...}, 'question': {...}}).

A matching rule gives its reply, and Fake records the call.

f = Fake({'GRADE': dict(correct=True)})
test_eq(ask_json(f, 'GRADE this'), dict(correct=True))
test_eq(len(f.calls), 1)

After a reply that is not JSON, ask_json asks again and gets the JSON.

bad = Fake(dict(X=lambda p, sp: 'oops' if 'not valid' not in p else '{"ok": 1}'))
test_eq(ask_json(bad, 'X'), {'ok': 1})

With need, a reply must be one JSON object with text in each of those keys. A list, or an object with no question, gets one more try. A second bad reply raises a ValueError that names the key.

odd = Fake(dict(Q=lambda p, sp: '{"question": "What is a rank?"}' if 'must be one JSON object' in p else '[1, 2]'))
test_eq(ask_json(odd, 'Q', need=('question',)), {'question': 'What is a rank?'})
test_fail(lambda: ask_json(Fake(dflt={}), 'Q', need=('question',)), contains='question')

A model for each task

The tutor does five tasks, and each task can use its own model. A quick model can grade and give hints. A strong model can write questions and lessons. The Settings page saves the choice. Router reads it on each call, so a change has an effect on the next call.

task what the model does
question writes a question and its hidden model answer
grade reads the conversation and grades it
hint gives the next hint
lesson teaches the smallest step after a miss
extract finds the concepts in a text

Each task also has a reply cap: the most tokens that the model can write in one reply. TOKENS gives the default of each task. A question has options and a rubric, and an extract can name 15 concepts, so these two get the most. A hint is short. The Settings page can change each cap. Only the cap is a setting, because ramabana’s oneshot uses no other per-call value: it turns thinking off, and the time limit of a model is in ramabana’s config.toml. The model layer gives the cap to the API models (OpenAI, Codex, Gemini, Copilot) and to the models on this Mac. Claude Code does not use it for the reply, but ramabana uses it to fit the prompt in the window of the model.

model_ask gives an ask for any model name. Install the models extra (pip install abhyasa[models]) to use the full list of models. With the extra, the name can be any model in that list: Claude Code, Codex, OpenAI, Copilot, Gemini, or a model on this machine (LiteRT, mlx, llama.cpp, Ollama). The call goes through the routing of ramabana, as route_ask below shows. Without the extra, the name goes to the model layer as it is.

Names for the model list

The Settings page shows a list of models. Each item has a name that people know, such as “Claude Sonnet” or “GPT-5.5”. The model id, such as claude/sonnet, is the value that the settings keep. model_label makes the name from the id. PROVIDERS gives the name of each group in the list, and provider_label reads it. ramabana’s is_local tells if a model runs on this Mac. For Ollama, it looks at the daemon host (the host in config.toml, else $OLLAMA_HOST), and it does not connect to it. Thus a model on an Ollama daemon on another computer has no “a local model” name, and its group is “Ollama on another computer”. Without the models extra, no local model is in the list, so no name says “a local model”.

One row for each model

Some models come through two providers. For example, Claude Haiku 5.5 comes through Claude Code and through GitHub Copilot, and GPT-6.1 Sol through Codex, GitHub Copilot and the OpenAI API. Each route has its own id, so the list showed the same name two or three times. one_each keeps one row for each name: the route of the first provider in ramabana’s READY_ORDER (subscriptions first, then keys). The row keeps the other ids in also. A saved id (keep) always stays, so the list shows the choice that you made.

Every call through ramabana

ramabana is the agent layer on top of the model layer. Its Routing sends each job to a model. When a cloud model fails or gives no answer, Routing puts it aside for five minutes and sends the job to the next route: other cloud models, then a small model on this Mac. Its backends stay open, so a call does not pay the start time of a new Chat.

ramabana_agent makes one ramabana Agent for the process, on the first call. The Agent gets only what Agent.oneshot needs:

  • NullHost: no folders, and each file operation is refused.
  • readonly=True, no sub-agents, no extensions, no skills, no lessons: no tool can write, run code or go on the network.
  • Approvals that refuse when nobody answers, and no saved rules.
  • cfg=None: no history, plan or run log, so the Agent writes no files.
  • A short briefing, so that it does not read skills or project files.

The turn of the Agent is the default model, so a task whose model fails goes to the default model first.

source

ramabana_agent

def ramabana_agent(
    turn:str=None
):

The one ramabana Agent of this process, made on first use on the turn dflt_model(turn): no folders, no tool that acts, no files.

Each task is a ramabana job with the same name. _point sets the model of the job before each call, only when the settings changed it. A model that ramabana put aside stays aside until its time is up.

ramabana_oneshot asks one question on the job of a task. ramabana’s Backend.oneshot does not wait when another call holds the backend: it gives ’’. So the call holds the abhyasa lock of each backend that it uses. Agent.oneshot calls fits(b) just before it asks the backend b, on the first route and on each fallback. fits lets go of the lock of the route before, then waits for the lock of b. A call holds one lock at a time, so two calls cannot wait for each other. When no route gives an answer, the call raises.

A failure can take some time: ramabana tries each route in turn, then the small model on this Mac. It puts a failed cloud model aside for five minutes.

A route can also raise ramabana’s OneshotTimeout when a call goes past its deadline. timeout_error changes it into the same RuntimeError as a call with no answer. The error names the model and the seconds, so each caller catches one kind of error.

prepare lets the caller change the text for each route, as ramabana’s Agent.oneshot does. The guide uses it for its guard: the guard then knows if the model of the route is on this Mac. HOSTED is the model that a guard takes when it does not know the route.

The worker agent

ramabana_worker makes a second ramabana Agent, for the gather agent of research. It is never the one Agent of ramabana_agent, so a long gather never holds a one-shot call. It runs on the default routing (Routing(turn=dflt_model())). Its host is the shalya host (default: a NullHost, with no folders). The caller names its tools in tools, then adds them with add_tool. ramabana’s only_tools offers the model only those tools, and refuses a tool with another name. ramabana’s memory and plan tools are held back. It has no approvals listener, so a tool that writes is refused. The caps stop a turn after max_calls tool calls, max_steps model steps, max_tokens tokens or max_cost dollars. A model such as Claude Code on a plan reports no cost. Then ramabana estimates the dollars from the tokens at the price of the model (ramabana.agent.token_rate), and keeps the estimate in estimated, so the dollar cap still holds.

ramabana_worker

def ramabana_worker(
    tools:list=(), host:NoneType=None, sp:str='You are the source gatherer of abhyasa, a tutor.', turn:str=None,
    max_calls:int=300, max_steps:int=80, max_cost:float=5.0, max_tokens:int=2000000
):

A new ramabana Agent on the turn dflt_model(turn), with the shalya host (default: no folders). The model sees only the tools named in tools, when the caller adds them. Never the agent of ramabana_agent. A turn stops at max_tokens tokens, and at max_cost dollars (estimated from the tokens when the model reports no cost).

The worker offers only the tool that the test names and adds. It is a new Agent each time, and never the shared one. The caps reach the Agent.

if _has_ramabana():
    def look(q:str, # what to look for
             ) -> str:
        "Look for `q`."
        return q
    w = ramabana_worker(['look'], max_calls=50, max_tokens=1000)
    w.add_tool(look)
    test_eq([t.__name__ for t in w.tools], ['look'])
    assert w is not ramabana_worker() and w is not ramabana_agent()
    test_eq((w.readonly, w.subagents, w.tool_budget, w.max_cost, w.max_tokens), (True, False, 50, WORKER_DOLLARS, 1000))

The worker refuses a tool that tools does not name. A worker with no names offers no tool, so ramabana’s own tools stay out.

if _has_ramabana():
    def write(path:str, # the file
              ) -> str:
        "Write `path`."
        return path
    test_fail(lambda: w.add_tool(write), contains='not in only_tools')
    test_eq(ramabana_worker().tools, [])

When the model reports no cost, ramabana estimates the dollars from the tokens with its own price table (est_rate is None), and keeps them in estimated. A new worker has estimated nothing, and has the default token cap.

if _has_ramabana():
    w = ramabana_worker()
    test_eq((w.est_rate, w.estimated, w.max_tokens), (None, 0., WORKER_TOKENS))

The lead of research is made by ramabana’s mk_agent. It offers ramabana’s read and web tools and delegate_search, and the tool that the test adds. It has no tool that writes a file or runs a command. The folder of the learner is open for reads only.

Tests of the route

These tests use a ramabana Agent with fake backends from ramabana.testing, so no model runs. using(a) puts that Agent in place of the real one for one test. CI does not install the models extra, so these tests run only when ramabana is installed.

from contextlib import contextmanager
from collections import Counter
from concurrent.futures import ThreadPoolExecutor
if has_rama:
    from ramabana.core import resolve
    from ramabana.testing import fake_agent, FakeBackend
@contextmanager
def using(a):
    "Use the `Agent` `a` in place of the real one, for one test."
    _ra['agent'] = a
    try: yield a
    finally: _ra.pop('agent', None)

Each task goes to the ramabana job with the same name. The task that the settings name gets its model, the other tasks get the default. Each call asks for the reply cap of its task, TOKENS[task], so a long question with its rubric is not cut.

if has_rama:
    a, be = fake_agent()
    jobs, one = [], a.oneshot

Slow is a fake backend that takes a moment to answer. It sets inside when a call starts.

if has_rama:
    class Slow(FakeBackend):
        "A fake backend that answers after 0.2 s and sets `inside` when a call starts."
        def __init__(self, *a, **kw): super().__init__(*a, **kw); self.inside = threading.Event()
        def _oneshot(self, prompt, sp, max_tokens): self.inside.set(); time.sleep(0.2); return f'ONESHOT:{prompt}'

The next tests need ramabana’s real Routing, so that a failed model goes to its next route. routed_agent gives a fake Agent with the real Routing on two fake models: fake-main, the default, and fake-quick. They are hosted models with a fake key, so Routing takes them on any machine. make(spec) gives the fake backend of each model, and bes keeps them by name.

if has_rama:

    for n in ('fake-main', 'fake-quick'): register_model(n, f'fakevendor/{n}', runtime='remote', api_key_env='ABHYASA_FAKE_KEY')

    def routed_agent(make):
        "A fake `Agent` on the real `Routing`, with the turn on `fake-main`. Returns the `Agent` and the backends by model name."
        a, _ = fake_agent(routing=Routing(turn='fake-main'))
        del a._be_or_none   # the real one, which asks `Routing`
        bes = {}
        def be(job='turn'):
            s = a.routing.spec(job)
            if s.name not in bes: bes[s.name] = make(s)
            return bes[s.name]
        a._be = be
        return a, bes
